## 4. Key decisions (not obvious from code)

**Product**

- Days 1–65 only (no weeks/weekdays shown to engineers). Lessons any day; target Day 65 within 90 calendar days (+ pause days). Steps Prep/Learn/Mock/Write in any order, **daily quiz last** (5 questions: 3 mcq, 1 scenario, 1 written; no pass mark). Assessment after every 5th day (60% on multiple choice to continue). Gates after Days 20 and 40; final review Day 65.
- **New Google sign-ins start as active engineers** enrolled from that day (7 Oct 2026; replaces "pending until approved"). `INITIAL_ADMIN_EMAILS` is empty for now (user decision): the only admin is the test account `admin@test.local` (via `/dev-login`); prateek@tequity.tech is an engineer enrolled from 7 Oct. Google is configured (`ALLOWED_EMAIL_DOMAIN=tequity.tech`).
- Test accounts: `/dev-login` accepts only `@test.local` (seeded: admin@, priya@, omar@ managers, neha@, aarav@, meera@, rohan@ engineers).
- Several admins allowed. 3 confirmed M0 rules: an admin can't change their own role/access; approving an engineer needs a team + start date; pauses can't overlap, ≤ 30 days, not before the start date.
- **Content is written once from the PDF (no pipeline).** Claude wrote all lessons word for word (errata fixed) and all questions (each quotes its PDF passage). **No admin content review (user decision, 7 Oct 2026): everything imported is live.** A day opens once imported; the quiz draws from the whole pool. The user checks the course from the engineer pages and reports problems; fix = edit `content/` + `pnpm content:import`. Re-import: a changed row replaces the old one; a changed question → new version (quiz items keep their snapshot); a removed question → deleted, or `retired` if already asked (never picked again).
- **The engineer books check-ins and gates** with their manager (PDF setup step 5; user, 9 Oct 2026). Never write "your manager books it". The portal reminds (Day-1 note, My plan/Home show "Book it with your manager · around <expected date>") and the manager sees Due/Overdue; no calendar integration yet.
- Wording rule: where the PDF refers to the plan's own schedule ("By Friday", "Week 1 Thursday"), content says day numbers ("By Day 5", "Day 4"); CareBook story dates stay.
- Content rows are stored as validated jsonb + key columns (not one table per §4 entity).
- "Today" uses the setting `plan.timezone` (default **Asia/Kolkata**) — _assumption, user to confirm_.
- **Light theme is the default**; dark only via the top-bar toggle (remembered per browser).
- LLM (Anthropic `claude-haiku-5-5` via Vercel AI SDK, switched from OpenRouter on 15 Oct 2026) is for **scoring only**. Real-project answers are not AI-scored until the user approves (`ai.scoreRealProjectAnswers=false`).
- External services (Anthropic, Resend, Google) sit behind interfaces with **fakes**; the real ones switch on when the user adds keys to `apps/api/.env`.

**Architecture/privacy**

- Browser never touches the DB. App connects as `app_user` (no BYPASSRLS); every user query runs in `PrismaService.withUser` (sets `app.user_id`); role read from DB. RLS ENABLE + FORCE on every table; SECURITY DEFINER functions pin `search_path = pg_catalog, public, pg_temp`. Step entries and daily quiz items are private to the engineer (no manager/admin read); card AI prompts are admin-only, engineers copy them through `app.card_prompt()` (audited `prompt.copied`).
- Mutating API calls need header `x-portal-request: 1` + matching Origin. Errors are typed codes in `packages/contracts/src/errors.ts` (add the HTTP status in `apps/api/src/common/api-error.ts` too).
- Concurrency: per-day advisory lock (`lockDay`) in start quiz / save step / answer; day completion upserts `day_progress`.

## 6. Gotchas learned in session 1

- A shell hook rewrites commands through `rtk`; prefix `rtk proxy` (e.g. `rtk proxy pnpm test`) to see raw output. zsh aborts a whole command line on an unmatched glob.
- No poppler on this Mac: PDF text was extracted with a Swift + PDFKit script (`docs/pdf-text.txt` is the result; table cells in it are often interleaved).
- Vite: `optimizeDeps.entries = src/**/*.tsx` is needed, otherwise lazy routes trigger a re-bundle + page reload on first visit (broke e2e).
- e2e runs against the shared local DB: `m1-day.spec.ts` resets neha's progress and does Day 1; `test:db` briefly swaps Days 1–2 content for fixtures (and retires the real Day 1 questions meanwhile) and restores them; `pnpm content:import` repairs it after an interrupted run. The dev-login rate limit (20/min) is handled in the e2e `signIn` helper (waits and retries).
- IDE TypeScript diagnostics in this repo are often stale/wrong (wrong tsconfig); trust `pnpm typecheck`.
- `.prettierignore` excludes `docs/design` (the mockup is kept exactly as published).
